## Content Writing Guidelines

### Tone and Style
- **Professional but approachable**: Technical accuracy with user-friendly language
- **Clear and concise**: Avoid jargon, explain technical terms
- **Action-oriented**: Use active voice, clear instructions
- **Inclusive**: Consider users of all technical levels

### Structure Guidelines
- **Scannable**: Use headers, bullet points, and visual breaks
- **Progressive disclosure**: Basic info first, advanced details later
- **Cross-referenced**: Link between related sections
- **Mobile-friendly**: Consider mobile readers

### Visual Guidelines
- **Consistent screenshot style**: Same window size, clean backgrounds
- **Annotated screenshots**: Highlight important elements
- **High quality**: Clear, readable text and UI elements
- **Accessible**: Alt text for images, good contrast

## Success Metrics

### User Experience Goals
- **Time to first success**: Users can get basic functionality working in under 10 minutes
- **Setup completion rate**: High percentage of users complete full setup
- **Feature discovery**: Users understand and use advanced features
- **Support reduction**: Fewer support requests due to clear documentation

### Content Quality Goals
- **Clarity**: Technical accuracy with clear explanations
- **Completeness**: All features and use cases covered
- **Currency**: Screenshots and instructions stay up-to-date
- **Accessibility**: Usable by developers of all experience levels
